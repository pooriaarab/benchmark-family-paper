The agent benchmarks closest to ours already grade what the agent does: SWE-bench scores repository edits against the project's own tests~\cite{jimenez2024swebench}, WebArena checks the state a browser agent leaves behind~\cite{zhou2024webarena}, $\tau$-bench compares the database to the goal after a simulated dialogue~\cite{yao2025taubench}, AgentBench spreads the question across environments~\cite{liu2024agentbench}, and BFCL scores function calls, including abstention~\cite{patil2025bfcl}. We share the habit of grading a trace against a state; the difference is the unit of distribution, one npm package with a mock provider and a grader a second machine can run with no key. Harnesses such as HELM~\cite{liang2023helm}, the EleutherAI evaluation harness~\cite{gao2023lmeval} and Inspect~\cite{aisi2024inspect} package the other direction: they are places to bring a model, and \texttt{benchmark-core} is a place to bring a task set.

Contamination and saturation are why a small public suite is a weak leaderboard. Sainz and colleagues argue that a model trained on a test split will look better than it is, and that the field should measure that per benchmark~\cite{sainz2023contamination}; Dehghani and colleagues showed that swapping the benchmark can reorder methods that people had treated as ranked~\cite{dehghani2021lottery}. The suite's answer is smaller: generators are seeded, the public seed is in the provenance command, and a hidden split is generated by a documented flag and kept out of the package.

Reward hacking is the formal version of a grader that can be gamed. Skalse and colleagues define a proxy as hackable when improving the proxy can make the true objective worse~\cite{skalse2022hacking}; a benchmark grader is a proxy, and we do not prove ours unhackable. The family writes down the cheap policies that should not win, and Sections~\ref{sec:prereg} and \ref{sec:soundness} measure where the released graders still pay them.

The measurement-quality frameworks we borrow from are external. BetterBench scores benchmark practice across design, implementation, documentation, and maintenance~\cite{reuel2024betterbench}; Bean and colleagues reviewed 445 benchmarks and found construct validity justified in 53.4 percent of them, with statistical tests or uncertainty reported in 16.0 percent~\cite{bean2025construct}; the Agentic Benchmark Checklist asks for an automatic oracle solver and trivial-agent baselines, which our oracle and trivial scripts answer on all but one package (Appendix~\ref{app:validity})~\cite{zhu2025abc}. The newer packages borrow threat models from published instruction-hierarchy, prompt-injection, memory and accessibility evaluations~\cite{wallace2024instruction,zhang2025iheval,debenedetti2024agentdojo,in2026permembench,w3c2024wcag22}. This paper measures what coding agents produce when they build one, and what probing review finds afterwards.
