Coding agents built the \suitePackages{} benchmark packages in this suite, \suiteTasks{} tasks on one shared engine, and every package passed its tests while \councilMergedApproved{} of the \councilMergedFeature{} merged feature pull requests carried an LLM approval. Probing the running packages still found defects that needed a fix round in every one of them, and most were found by attack policies written against each package's own task shape; the generic checks the benchmark literature prescribes missed almost all of them.

Benchmarks steer model choice, safety claims and research agendas, and a score is only as good as the grader behind it. Coding agents have made a benchmark cheap to build: a task set, a deterministic grader and runnable surfaces in days. Verification has not become cheap. The usual gates are unit tests, continuous integration and a reviewer reading the diff, and the published checklists add an oracle solver and a trivial agent~\cite{reuel2024betterbench,zhu2025abc}. This paper measures what those gates miss on \suitePackages{} real packages, and what a deeper review finds.

The record behind every number is public. All \reviewPackages{} packages needed at least one fix round (median \reviewRoundsMedian{}, maximum \reviewRoundsMax{}) across \defectClasses{} defect classes, and at least \defectBlindStrategyCredit{} paid credit to a strategy that ignored the task. Re-measured on the shipped tarballs, \expExplReplicated{} of \expExplRecordClauses{} logged exploit clauses replicate, and the median attack score falls from \expExplAtkMedianOld{} at the pre-fix release to \expExplAtkMedianNew{} at the fixed one. The approvals were not rubber stamps: the review workflow raised open Critical or Major items on about \councilSeverityPrsRead{} pull requests, and the record documents \approvalDefectCases{} cases where an approval stood behind a defect a later probing review found. Under the preregistered design the best of \trivialPolicies{} generic blind policies scored higher before the fixes in only \trivialHigherOld{} of \trivialPackages{} packages ($p = \trivialSignP{}$), and at the released versions the best blind score on any package is \expTrivialReleasedMax{}. The reviewer sessions were agent sessions the author configured and handed a protocol, there is no human-built control, and no real model has been run, so this paper claims nothing about any model's ability.

The artifact underneath is \texttt{benchmark-core}, a shared TypeScript engine: one \texttt{defineBenchmark} call produces an SDK import, a command-line interface, an MCP server and a fetch-style HTTP handler per package, and a mock provider runs every grader offline with no key, so a second machine can check them all. Figure~\ref{fig:system} shows the shape; the packages are published on npm and listed at \url{https://aibenchmarkindex.com}.

Our contributions are:
\begin{enumerate}
\item a sourced taxonomy of \defectClasses{} defect classes across \suitePackages{} agent-built packages, with a fix-round record of \reviewRoundsTotal{} briefs (Section~\ref{sec:review});
\item a re-measurement of the logged exploits on the published tarballs, separating what the record claimed from what replicates (Section~\ref{sec:review}, Table~\ref{tab:exploit-verdicts});
\item a preregistered check of the trivial-agent gate and an extended blind-policy battery over every pinned artifact (Section~\ref{sec:prereg});
\item the artifact itself: one engine, \suitePackages{} packages with four surfaces each, provenance and a licence per task source (Appendices~\ref{app:suite} and \ref{app:engine});
\item five checks to run before an agent-built benchmark ships: solvable from the model's view, blind policies lose, honest answers win, held out means held out, and nothing is taken on trust (Section~\ref{sec:conclusion}).
\end{enumerate}
