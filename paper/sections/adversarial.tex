Most packages in the suite went through a reviewer who was not the author and whose job was to break the grader, not to approve it; the public trackers record that review for apology-pizza (issue 7) and memory-conflict (issues 15 and 23), and only schema-mutation has no named review record. The first twelve packages in the suite were reviewed after their 0.1.0 releases, and each shipped a 0.2.0 whose changelog states that 0.1.0 scores are not comparable. Six of the ten later packages (crm-truthfulness, accessibility-fix, silent-constraints, rollback-recovery, schema-mutation, and payment-delegation) record the same class of fixes in their changelogs; latency-budget and memory-conflict log only the initial release, and exploit-resistance and instruction-hierarchy record the same protections inside their initial-release feature lists rather than as fixes. The list below comes from those public changelogs, grading notes, issues, and pull-request threads, not from memory. It is process evidence, not proof of correctness: it shows that review found real defects, not that none remain.

\begin{itemize}
\item \textbf{Unsolvable tasks.} At least three packages shipped a task a perfect agent could not pass. Hundred-step's run limits (60 s, 12 turns, 24 tool calls) timed out a correct agent on long episodes before the limits were made to scale with task length. Schema-mutation printed money as \texttt{97.8} where the expected call wanted \texttt{97.80}, so the task could not be solved from the visible prompt. Pelican measured checks its prompts never stated, and the changelog records them deleted or restated.

\item \textbf{Constant and blind strategies scored high.} At least sixteen packages record a strategy that ignored the task and still earned real credit. Checkout-consent gave up to 0.75 to a trace that never reached a pay or a decline; hundred-step could be gamed into a finished flag with zero recoveries; honesty's headline let always-abstain and always-answer policies ride on half the suite; sycophancy, crm-truthfulness, mcp-safety, ranking-stability, tool-errors, silent-constraints, pelican, exploit-resistance, instruction-hierarchy, accessibility-fix, rollback-recovery, latency-budget, and memory-conflict record their own versions of the same hole.

\item \textbf{Honest answers scored zero.} At least eight packages failed well-formed submissions over formatting alone. Pelican's scanner rejected a correct drawing inside a code fence, behind an XML prolog, or next to a comment; honesty, skateboard, ranking-stability, checkout-consent, and tool-errors record the same class of fix: strip one fence, take the last JSON object, and normalise case, whitespace, money, and units. Exploit-resistance takes the first fenced block ahead of grading, and schema-mutation's tracker records a grader that rejected equivalent answers and common wire formats.

\item \textbf{Hidden splits that were not hidden.} Every one of the first twelve packages changed its hidden-split handling at 0.2.0. Two failure shapes recur in the changelogs and pull-request threads: a split that reproduced public items (ranking-stability's ordering family regenerated the same prompts; honesty had public-answer overlaps) and a split that could ship inside the npm tarball (sycophancy's publishing leak, recorded in pull request 20 rather than a changelog; the moved output paths recorded by pelican and payment-delegation; schema-mutation's move into \texttt{.hidden/}, which sits under Unreleased so the measured 0.1.0 lacks it; and silent-constraints' tarball exclusion paired with an \texttt{-{}-out} filename guard). At least eleven packages had also published a seed that reproduces the hidden split: hundred-step named it in provenance, ranking-stability served it in task metadata, and nine more shipped a concrete seed against the \texttt{-{}-split hidden} command in their docs.

\item \textbf{The SDK task-list cache.} Two packages record the same trap: a benchmark object cached its task list, so pointing the SDK at a held-out file silently re-scored the public split. Mcp-safety removed \texttt{setTasksPath} for exactly this reason, and skateboard now builds a fresh benchmark per call. Payment-delegation's changelog records a twin case, a task file rewritten at the same path re-reading instead of serving the first parse.

\item \textbf{Breakdowns the engine dropped.} Per-row grader details did not survive the shared surfaces, so each package that promises a breakdown recomputes it in-package. Pelican's \texttt{mcp} command ran the engine's bare server, so \texttt{run\_benchmark} returned no \texttt{checkSummary} until the route was pointed at the package's own server; tool-errors records the identical fix.

\item \textbf{Forged report rows accepted.} Report endpoints trusted the scores they were given. Apology-pizza's grading notes now state the rule plainly: submitted scores, reasons, means, and intervals are ignored, and every row is re-graded from its tool log. The shared engine already works that way: each package's \texttt{score} command re-grades the submitted rows from their stored submissions (a forged schema-mutation report claiming a mean of 1.0 re-scored to 0.5), and several packages document the rule on their own surfaces, for example silent-constraints' \texttt{score} and exploit-resistance's \texttt{/v1/report}.

\item \textbf{An evaluator a crafted answer could escape.} Test-weakening 0.1.0 evaluated model-written JavaScript in the benchmark's own process through \texttt{Function(...)} behind a syntax allow-list, and a member name computed at run time could reach \texttt{constructor}. Version 0.2.0 replaces it with a parser and a tree-walking interpreter for a closed grammar inside child processes (a pool of four) that can be killed, and 0.1.0 is deprecated on npm with a security note.

\item \textbf{Documentation ahead of the code.} At least three packages published grading notes or README claims for checks that did not exist or numbers nobody had measured. Sycophancy's notes claimed a courtesy check for slurs the pattern did not contain; pelican printed prompt-only solvability numbers that an independent policy then measured lower; hundred-step's README said dependency tokens could not be guessed while its own error messages returned them.

\item \textbf{Generator bugs.} Accessibility-fix wrote \texttt{href="undefined"} into nine of thirteen hard prompts, and a stray background draw could make a reference page fail its own grader. Ranking-stability's ordering family never called its own random source, so every ordering answer was the first name in the prompt. Hundred-step accepted \texttt{advance} calls past the final step.

\item \textbf{Lexical detectors that do not generalise.} Crm-truthfulness scores forbidden-phrase traps by anchored rules. An independent review built an unseen table of 96 trap lines, 12 obeyed and 12 honest for each of the four trap kinds, and ran every line on each task of its matching scenario, 240 scorings per side. It recognised 52 percent of the honest refusals, so a missed refusal lands at the same 0.40 cap as an obeyed trap plus one real fact. The package ships as alpha with that miss rate documented rather than fixed by a longer word list. Honesty's claim detectors made the same class of error on the prose around a JSON answer and were removed; the graded field is now only the answer.

\item \textbf{Prompts looser than the grader.} Pelican's documented limits record prompts that state a bound the grader measured more strictly (a beak ``at least a third'' of the body against a check that needed 0.35), so the package tells the reader to draw with a margin. Honesty scored a confidence field its prompt never defined.
\end{itemize}

Two things follow. First, every 0.2.0 changelog says its scores are not comparable to 0.1.0, so a published mean that does not name its package version is not reproducible; Table~\ref{tab:suite} carries the versions for that reason. Second, none of this proves a grader right. It is evidence that the failure modes were looked for, measured, and written down where anyone can check them again.
