Probing review found defects in every package after the builders' gates and the council's reviews had run. This section reports the record: who built the packages, who reviewed them, and what broke. Every count below is a sourced minimum drawn from a public changelog, issue, grading note, or pull-request thread; Table~\ref{tab:defects} names the source per class, Appendix~\ref{app:locators} lists the locator behind every package cell, and Figure~\ref{fig:defects} charts the counts. The council approved \councilMergedApproved{} of the \councilMergedFeature{} merged feature pull requests; the record documents \approvalDefectCases{} of those approvals standing behind defects the probing review found later (pelican's pull request 4, issue 8; sycophancy's pull request 20, approved while a publishing leak and a grading-note claim the code did not back were still in the tree), and of the defects cited in Table~\ref{tab:defects} one was flagged by the council itself: the published hidden seed on sycophancy's pull request 20, which shares the hidden-split cell with that request's probing-found leak. The record shows that review found real defects. It does not show that none remain.

\paragraph{Who built, and who reviewed.}
Table~\ref{tab:builders} counts the \texttt{Assisted-by} trailers on the \buildersPrs{} pull requests across the \suitePackages{} repositories, read from the request bodies on 2026-10-16 (\texttt{paper/data/builders.csv}, rebuilt by \texttt{scripts/builders.mjs}). Every request carries a trailer, so the suite was built mainly by coding agents, and several agents share the work.

\paragraph{Approval-style review.}
The council workflow was the other review layer. On the pull-request record, the \texttt{claude} account it posts under authored \councilReviews{} reviews on \councilPrsReviewed{} of the \buildersPrs{} pull requests in the \suitePackages{} repositories: \councilApproved{} approvals, \councilCommented{} comment reviews, and \councilChanges{} change requests (\texttt{paper/data/council.csv}, rebuilt by \texttt{scripts/council.mjs} from the GitHub API on 2026-10-16). Coverage was not total: of the \councilMergedFeature{} merged feature pull requests, \councilMergedNoReview{} carry no council review, \councilMergedNoApproval{} were reviewed but never approved, and \councilMergedCheckFail{} merged while the council check showed a failure on the head commit. Only \councilMergedApproved{} of the \councilMergedFeature{} merged feature pull requests carry a council approval.

The council read the diff and often had findings: \councilSeverityReviews{} of its reviews by the regex raise an open Critical or Major item, many of them about process, on at least \councilSeverityPrs{} pull requests (a regex estimate over review bodies, hand-checked on a \councilSampleSize{}-review stride sample, every k-th entry of the sorted list, where all \councilSampleSize{} agreed with the regex flag; a full read of the unflagged reviews finds \councilSeverityRegexMissed{} reviews the regex missed, while the \councilSeverityRegexFalsePositives{} false positive on record is a lower bound because the flagged reviews were not all re-read, so the real count is about \councilSeverityReviewsRead{} reviews on about \councilSeverityPrsRead{} pull requests; method in \texttt{paper/data/README.md}). On sycophancy's pull request 20 the council flagged the published hidden seed as an open Major, and the builder removed it before the request was approved and merged. What the council did not do is probe: its reviews read the diff and sometimes push fixes, but they do not run attack policies against the built package. Pelican's pull request 4 replaced string equality with the structural SVG scanner and earned a council approval written by the chair alone, both other members having timed out; issue 8 in the same repository then records that the grader discarded the task it was scoring, so one memorised SVG scored 1.0 on every public and hidden task. Sycophancy's pull request 20 is the second case: it was approved at commit \texttt{4ffa15c} while its generator still defaulted hidden plans into \texttt{data/}, a directory the npm package ships, and the docs claimed the courtesy check caught slurs; its pattern held six insult terms and no slurs. The probing review's released fix brief records both defects, and they were fixed in commit \texttt{7a60894} after the approval; the merged head \texttt{25c8d27} sits three commits after the approved one, and the council never re-reviewed the request. Those are \approvalDefectCases{} documented cases among \councilMergedApproved{} approvals on \councilMergedFeature{} merged feature pull requests where an approval stood behind a defect a probing review later found.

\paragraph{Probing review.}
Most cells in Table~\ref{tab:defects} cite an issue, pull request, or changelog line written against the probing sessions' findings; one cell, sycophancy's hidden-split entry, also carries a defect the council itself flagged on pull request 20, the published seed, while that request's publishing leak in the same cell and the courtesy claim behind the docs-ahead-of-code cell are probing findings. The probing sessions ran separate from the builders, instructed to distrust the builders' claims, write their own attack policies, and verify against running code. The author configured each of those sessions and handed it a protocol; the reviewers were agent sessions, so this paper calls the pass a probing review, and the protocol the first-round sessions followed is not released. The released protocol in Appendix~\ref{app:protocol} is the re-review one, which the re-check sessions used after fixes landed. Two things about these sessions are not verifiable on the public record. The first is authorship: the sessions ran in coding-agent interfaces, and the model behind them is not recorded in the repositories, so this paper does not name one. The second is coverage: a defect class nobody thought to probe would not appear. What the record does show is the output: findings, fixes, and locators that anyone can check again.

\paragraph{What the record shows.}
All \reviewPackages{} packages needed at least one fix round before or after release, with a median of \reviewRoundsMedian{} rounds and a maximum of \reviewRoundsMax{} (Figure~\ref{fig:rounds}; data in \texttt{paper/data/review-rounds.csv}). The first \reviewWaveOne{} packages each shipped a 0.2.0 whose changelog states that 0.1.0 scores are not comparable. That sentence alone is weak evidence, because the fix briefs the builders worked from required it verbatim; what makes it meaningful is that the scoring changes behind it are real and on the same record. Checkout-consent moved a trace that never reaches a pay or a decline from up to \noteCheckoutNeverPay{} to 0, pelican moved a memorised drawing from 1.0 on every task to at most \notePelicanMemoCap{}, and honesty moved a policy that looked up the fact and always answered null from a headline of \noteHonestyAbstainMean{} to near 0 (per-package locators in Appendix~\ref{app:locators}). The later packages crm-truthfulness, accessibility-fix, silent-constraints, rollback-recovery, schema-mutation, and payment-delegation record the same class of fixes in their changelogs; latency-budget and memory-conflict log only the initial release, and exploit-resistance and instruction-hierarchy record the same protections inside their initial-release feature lists. The classes below come from those public changelogs, grading notes, issues, and pull-request threads. It is process evidence, and it proves no grader correct.

\begin{itemize}
\item \textbf{Unsolvable tasks.} At least \defectUnsolvableTasks{} packages shipped a task a perfect agent could not pass. Hundred-step's fixed run limits timed out a correct agent on long episodes before the limits were made to scale with task length. Schema-mutation printed a money amount with one decimal where the expected call wanted two, so the task could not be solved from the visible prompt. Pelican measured checks its prompts never stated, and the changelog records them deleted or restated. Silent-constraints' prompt ``Resolve every ticket about the <topic>'' told the agent to touch an out-of-scope ticket, and doing exactly that scored 0 on two ticket tasks.

\item \textbf{Violations that were not penalised.} Silent-constraints scores a met goal with zero invariant violations as the headline, yet a clean solution that also shared every file with an outside address passed on \noteSilentFileLeak{} file tasks, and a solution with extra internal spam sends passed on \noteSilentMailSpam{} mail tasks. An unpunished violation on top of a solved task is a different defect from a blind strategy, so it gets its own class.

\item \textbf{Constant and blind strategies scored high.} At least \defectBlindStrategyCredit{} packages record a strategy that ignored the task and still earned real credit. Honesty's headline gave a policy that looked up the fact and always answered null a mean of \noteHonestyAbstainMean{}; pelican, tool-errors, mcp-safety, sycophancy, ranking-stability, crm-truthfulness, instruction-hierarchy, memory-conflict, accessibility-fix, rollback-recovery, apology-pizza, and skateboard record their own versions of the same hole. The preregistered check measured the same class directly on checkout-consent, where the best generic trivial policy scored 0.250 at 0.1.0 and 0 at 0.2.0 (Section~\ref{sec:prereg}); checkout-consent's review issue reads weaker because its traces build the right cart, and latency-budget's stays outside the count: issue 9 there is open and gives no measured score. Borderline cases stay outside the count too: hundred-step let an agent read dependency tokens out of error messages and reach \texttt{final=true} with zero recoveries (about \noteHundredStepTokenLeak{}), a leak exploit that stays outside this count, and exploit-resistance's always-\texttt{cannot\_fix} policy scored \noteExploitRefusalScore{} until the fix lowered the refusal credit to \noteExploitRefusalCredit{}.

\item \textbf{Honest answers scored zero.} At least \defectHonestAnswerRejected{} packages failed well-formed submissions over formatting alone. Pelican's scanner rejected a correct drawing inside a code fence, behind an XML prolog, or next to a comment; honesty, skateboard, ranking-stability, checkout-consent, and tool-errors record the same class of fix: strip one fence, take the last JSON object, and normalise case, whitespace, money, and units. Exploit-resistance takes the first fenced block ahead of grading, and schema-mutation's tracker records a grader that rejected equivalent answers and common wire formats.

\item \textbf{Hidden splits that were not hidden.} Every one of the first \reviewWaveOne{} packages changed its hidden-split handling at 0.2.0. Two failure shapes recur in the changelogs and pull-request threads: a split that reproduced public items (ranking-stability's ordering family regenerated the same prompts; honesty had public-answer overlaps) and a split that could ship inside the npm tarball (sycophancy's publishing leak, recorded in pull request 20; the moved output paths recorded by pelican and payment-delegation; schema-mutation's move into \texttt{.hidden/}, which sits under Unreleased so the measured 0.1.0 lacks it; and silent-constraints' tarball exclusion paired with an \texttt{-{}-out} filename guard). At least \noteHiddenSeedPublished{} packages had also published a way to regenerate the hidden split: hundred-step named the seed in its provenance, ranking-stability served it in task metadata (the later issue 15), sycophancy committed its default hidden seed and generator to the public repository (the council flagged the seed on pull request 20 as an open Major, and the builder removed it before that request merged), and ten more READMEs print a concrete seed in the \texttt{-{}-split hidden} example (accessibility-fix, apology-pizza, checkout-consent, cost-per-task, exploit-resistance, mcp-safety, pelican, schema-mutation, skateboard, and test-weakening). Those are examples in current documentation; nothing shows each seed was a real held-out one.

\item \textbf{The SDK task-list cache.} At least \defectTaskListCache{} packages record the same trap: a benchmark object cached its task list, so pointing the SDK at a held-out file silently re-scored the public split. Mcp-safety removed \texttt{setTasksPath} for exactly this reason, skateboard now builds a fresh benchmark per call, and payment-delegation's changelog (under Unreleased) records a twin case, a task file rewritten at the same path being re-read on the next parse.

\item \textbf{Breakdowns the engine dropped.} At least \defectDroppedBreakdowns{} packages record per-row grader details that did not survive the shared surfaces, so each package that promises a breakdown recomputes it in-package. Pelican's \texttt{mcp} command ran the engine's bare server, so \texttt{run\_benchmark} returned no \texttt{checkSummary} until the route was pointed at the package's own server; tool-errors records the identical fix.

\item \textbf{Forged report rows accepted.} Apology-pizza's \texttt{/v1/score-report} trusted the scores it was given, so a forged report returned a mean of 1. Its grading notes now state the rule plainly: submitted scores, reasons, means, and intervals are ignored, and every row is re-graded from its tool log. The shared engine already works that way: each package's \texttt{score} command re-grades the submitted rows from their stored submissions, and several packages document the rule on their own surfaces, for example silent-constraints' \texttt{score} and exploit-resistance's \texttt{/v1/report}.

\item \textbf{An evaluator a crafted answer could escape.} Test-weakening 0.1.0 evaluated model-written JavaScript in the benchmark's own process through \texttt{Function(...)} behind a syntax allow-list, and a member name computed at run time could reach \texttt{constructor}. Version 0.2.0 replaces it with a parser and a tree-walking interpreter for a closed grammar inside child processes that can be killed (the pool size is \texttt{EVALUATOR\_POOL\_SIZE = 4} in \texttt{src/sandbox.ts} line 15 of the package), and 0.1.0 is deprecated on npm with a security note.

\item \textbf{Documentation ahead of the code.} At least \defectDocsAheadOfCode{} packages published grading notes or README claims for checks that did not exist or numbers nobody had measured. Sycophancy's notes claimed a courtesy check for slurs the pattern did not contain; pelican printed prompt-only solvability numbers that a probing policy then measured lower; hundred-step's README said dependency tokens could not be guessed while its own error messages returned them.

\item \textbf{Generator bugs.} At least \defectGeneratorBugs{} packages shipped generators that broke their own task sets. Accessibility-fix wrote \texttt{href="undefined"} into \noteAccessUndefinedPrompts{} hard prompts, and a stray background draw could make a reference page fail its own grader. Ranking-stability's ordering family never called its own random source, so every ordering answer was the first name in the prompt.

\item \textbf{Lexical detectors that do not generalise.} At least \defectLexicalDetectorMiss{} packages score language with anchored rules that miss unseen wording. Crm-truthfulness scores forbidden-phrase traps by anchored rules. A probing review wrote \noteCrmTrapLines{} unseen trap lines, half obeyed and half honest, and ran each on all \noteCrmTrapTasks{} trap tasks. It missed \noteCrmObeyedMissed{} obeyed lines, and \noteCrmHonestCapped{} honest refusals landed at the \noteCrmTrapCap{} cap, below the vague-email score. The package ships as alpha documenting a different measure of the same weakness: 52 percent of honest refusals (\noteCrmDocHonestRate{}) were scored as honest in its own check, and the rest were missed. Honesty's claim detectors made the same class of error on the prose around a JSON answer and were removed; the graded field is now only the answer.

\item \textbf{Prompts looser than the grader.} At least \defectPromptLooserThanGrader{} packages stated a bound the grader measured more strictly. Pelican's documented limits record a beak ``at least a third'' of the body against a check that needed 0.35, so the package tells the reader to draw with a margin. Honesty scored a confidence field its prompt never defined.
\end{itemize}

\paragraph{What stays open.}
Not every finding closed. Crm-truthfulness ships as alpha with its lexical miss rate documented as a known limit. Pelican's structural check accepts drawings a person would reject and rejects some it would accept; that limit is documented and still open. Every package in this release reports status \texttt{\suiteStatus{}}.

\paragraph{Two things follow from the record.}
First, a published mean that does not name its package version is not reproducible: the 0.2.0 changelogs mark their scores incomparable with 0.1.0, the sentence was required by the fix briefs, and the scoring changes behind it are real. Table~\ref{tab:suite} carries the versions for that reason. Second, none of this proves a grader right. It shows that the logged failure modes were attacked and measured, and the record stays open to the next probe.
