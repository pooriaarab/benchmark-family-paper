Every package in the suite went through a reviewer who was not the author and whose job was to break the grader, not to approve it. The first twelve packages were reviewed after their 0.1.0 releases, and each of the twelve shipped a 0.2.0 whose changelog states that 0.1.0 scores are not comparable. The second-wave packages record the same class of fixes in their pre-release changelogs. The list below comes from those public changelogs, grading notes, and pull-request threads, not from memory. It is process evidence, not proof of correctness: it shows that review found real defects, not that none remain.

\begin{itemize}
\item \textbf{Unsolvable tasks.} At least three packages shipped a task a perfect agent could not pass. Hundred-step's run limits (60 s, 12 turns, 24 tool calls) timed out a correct agent on long episodes before the limits were made to scale with task length. Schema-mutation printed money as \texttt{97.8} where the expected call wanted \texttt{97.80}, so the task could not be solved from the visible prompt. Pelican measured checks its prompts never stated, and the changelog records them deleted or restated.

\item \textbf{Constant and blind strategies scored high.} Nine packages record a strategy that ignored the task and still earned real credit. Checkout-consent gave up to 0.75 to a trace that never reached a pay or a decline; hundred-step could be gamed into a finished flag with zero recoveries; honesty's headline let always-abstain and always-answer policies ride on half the suite; sycophancy, crm-truthfulness, mcp-safety, ranking-stability, tool-errors, and silent-constraints record their own versions of the same hole.

\item \textbf{Honest answers scored zero.} Seven packages failed well-formed submissions over formatting alone. Pelican's scanner rejected a correct drawing inside a code fence, behind an XML prolog, or next to a comment; honesty, skateboard, ranking-stability, checkout-consent, tool-errors, and apology-pizza record the same class of fix: strip one fence, take the last JSON object, and normalise case, whitespace, money, and units.

\item \textbf{Hidden splits that were not hidden.} Every one of the twelve wave-1 packages changed its hidden-split handling at 0.2.0. Two failure shapes recur in the changelogs: a split that reproduced public items (ranking-stability's ordering family regenerated the same prompts; honesty had public-answer overlaps) and a split that could ship inside the npm tarball (sycophancy's publishing leak, and the moved output paths recorded by pelican, schema-mutation, payment-delegation, and silent-constraints). Two packages had also published the hidden seed itself: hundred-step named it in provenance, and ranking-stability served it in task metadata.

\item \textbf{The SDK task-list cache.} Three packages record the same trap: a benchmark object cached its task list, so pointing the SDK at a held-out file silently re-scored the public split. Mcp-safety removed \texttt{setTasksPath} for exactly this reason, and skateboard and payment-delegation now build a fresh benchmark per call.

\item \textbf{Breakdowns the engine dropped.} Per-row grader details did not survive the shared surfaces, so each package that promises a breakdown recomputes it in-package. Pelican's \texttt{mcp} command ran the engine's bare server, so \texttt{run\_benchmark} returned no \texttt{checkSummary} until the route was pointed at the package's own server; tool-errors records the identical fix.

\item \textbf{Forged report rows accepted.} Report endpoints trusted the scores they were given. Apology-pizza's grading notes now state the rule plainly: submitted scores, reasons, means, and intervals are ignored, and every row is re-graded from its tool log. The shared re-grade path ships in eight packages.

\item \textbf{An evaluator a crafted answer could escape.} Test-weakening 0.1.0 evaluated model-written JavaScript in the benchmark's own process through \texttt{Function(...)} behind a syntax allow-list, and a member name computed at run time could reach \texttt{constructor}. Version 0.2.0 replaces it with a parser and a tree-walking interpreter for a closed grammar inside a killable child process, and 0.1.0 is deprecated on npm with a security note.

\item \textbf{Documentation ahead of the code.} At least three packages published grading notes or README claims for checks that did not exist or numbers nobody had measured. Sycophancy's notes claimed a courtesy check for slurs the pattern did not contain; pelican printed prompt-only solvability numbers that an independent policy then measured lower; hundred-step's README said dependency tokens could not be guessed while its own error messages returned them.

\item \textbf{Generator bugs.} Accessibility-fix wrote \texttt{href="undefined"} into nine of thirteen hard prompts, and a stray background draw could make a reference page fail its own grader. Ranking-stability's ordering family never called its own random source, so every ordering answer was the first name in the prompt. Hundred-step accepted \texttt{advance} calls past the final step.

\item \textbf{Lexical detectors that do not generalise.} Crm-truthfulness scores forbidden-phrase traps by anchored rules. On an unseen table of 240 honest refusal lines an independent review measured 52 percent recognised, so a missed refusal and an obeyed trap land at the same 0.40 cap. The package ships as alpha with that miss rate documented rather than fixed by a longer word list. Honesty's claim detectors made the same class of error on the prose around a JSON answer and were removed; the graded field is now only the answer.

\item \textbf{Prompts looser than the grader.} Pelican's documented limits record prompts that state a bound the grader measured more strictly (a beak ``at least a third'' of the body against a check that needed 0.35), so the package tells the reader to draw with a margin. Honesty scored a confidence field its prompt never defined.
\end{itemize}

Two things follow. First, every 0.2.0 changelog says its scores are not comparable to 0.1.0, so a published mean that does not name its package version is not reproducible; Table~\ref{tab:suite} carries the versions for that reason. Second, none of this proves a grader right. It is evidence that the failure modes were looked for, measured, and written down where anyone can check them again.
