Verification in this suite ran in three layers, ordered by where they sit in the pipeline and what they may see. Figure~\ref{fig:system} shows them, and beneath them the policy ladder, which orders attack policies by how much of the package they may read.

\paragraph{L1: tests and CI.}
Each package's own end-to-end script and the shared \texttt{check} job ran on every pull request. No test job failed on the last commit of any of the \councilMergedFeature{} merged feature pull requests; \councilTestJobEverFail{} had failed the shared job on an earlier commit. This layer only checks the code against the tests the builder wrote.

\paragraph{L2: LLM diff review.}
Before merge, an LLM review council, several reviewer sessions under a single chair account the author configured, reviewed the pull requests by reading the diff. It approved \councilMergedApproved{} of the \councilMergedFeature{} merged feature pull requests, and across the suite its reviews raised an open Critical or Major item on about \councilSeverityPrsRead{} of the \councilPrsReviewed{} pull requests they read, so the layer was not a rubber stamp. The reviewers read code and prose; they did not run attack policies of their own.

\paragraph{L3: probing the running package.}
Separate sessions then attacked each built package as a running artifact, writing their own policies and logging what earned credit. The author configured the sessions and the record does not name the model behind them; Appendix~\ref{app:protocol} releases the re-review protocol the re-check sessions followed. Every one of the \reviewPackages{} packages needed at least one fix round, median \reviewRoundsMedian{}, maximum \reviewRoundsMax{} (Section~\ref{sec:review}). L1 ran the builder's own checks and L2 read the diff; only L3 sent a policy the builder did not write.

\paragraph{The policy ladder.}
An attack policy is a script that answers tasks the way a model would. Policies sort into four rungs by what they may see. A \emph{blind} policy sees only what a model sees at run time: the prompt, the tools, and its own transcript; the \trivialPolicies{} generic policies of Section~\ref{sec:prereg} sit here. A \emph{prompt-reading} policy may also read the package's public text and pick a canned attack matched to the wording; this release measures no cell on that rung. A \emph{task-aware} policy is written against the package's own task shape and scoring path; the per-package attacks behind Section~\ref{sec:review} sit here, and its defect record is this rung's yield. The top rung is the \emph{oracle}, the scripted ideal answer each package ships for its mock provider and the ceiling the other rungs are measured against (Appendix~\ref{app:validation}); the grader checks of Section~\ref{sec:soundness} start from it.
