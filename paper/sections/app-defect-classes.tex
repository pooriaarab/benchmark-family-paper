\section{Defect classes, per class}
\label{app:defectclasses}
The detail behind Table~\ref{tab:defects}: each class with its examples and sourced minima. The locators for every package cell sit in Appendix~\ref{app:locators}, and the fix rounds per package in \texttt{paper/data/review-rounds.csv}.

\begin{itemize}
\item \textbf{Unsolvable tasks.} At least \defectUnsolvableTasks{} packages shipped a task a perfect agent could not pass. Hundred-step's fixed run limits timed out a correct agent on long episodes before the limits were made to scale with task length. Schema-mutation printed a money amount with one decimal where the expected call wanted two, so the task could not be solved from the visible prompt. Pelican measured checks its prompts never stated, and the changelog records them deleted or restated. Silent-constraints' prompt ``Resolve every ticket about the <topic>'' told the agent to touch an out-of-scope ticket, and doing exactly that earned nothing on \noteSilentTicketTasks{} ticket tasks.

\item \textbf{Violations that were not penalised.} Silent-constraints scores a met goal with zero invariant violations as the headline, yet a clean solution that also shared every file with an outside address passed on \noteSilentFileLeak{} file tasks, and a solution with extra internal spam sends passed on \noteSilentMailSpam{} mail tasks. An unpunished violation on top of a solved task is a different defect from a blind strategy, so it gets its own class.

\item \textbf{Constant and blind strategies scored high.} At least \defectBlindStrategyCredit{} packages record a strategy that ignored the task and still earned real credit. Honesty's headline gave a policy that looked up the fact and always answered null a mean of \noteHonestyAbstainMean{}; pelican, tool-errors, mcp-safety, sycophancy, ranking-stability, crm-truthfulness, instruction-hierarchy, memory-conflict, accessibility-fix, rollback-recovery, apology-pizza, and skateboard record their own versions of the same hole. The preregistered check measured the same class directly on checkout-consent, where the best generic trivial policy scored \expTrivCheckoutConsentOld{} at 0.1.0 and \expTrivCheckoutConsentNew{} at 0.2.0 (Section~\ref{sec:prereg}); checkout-consent's review issue reads weaker because its traces build the right cart, and latency-budget's stays outside the count: issue 9 there is open and gives no measured score. Borderline cases stay outside the count too: hundred-step let an agent read dependency tokens out of error messages and reach \texttt{final=true} with zero recoveries (about \noteHundredStepTokenLeak{}), a leak exploit that stays outside this count, and exploit-resistance's always-\texttt{cannot\_fix} policy scored \noteExploitRefusalScore{} until the fix lowered the refusal credit to \noteExploitRefusalCredit{}.

\item \textbf{Honest answers scored zero.} At least \defectHonestAnswerRejected{} packages failed well-formed submissions over formatting alone. Pelican's scanner rejected a correct drawing inside a code fence, behind an XML prolog, or next to a comment; honesty, skateboard, ranking-stability, checkout-consent, and tool-errors record the same class of fix: strip one fence, take the last JSON object, and normalise case, whitespace, money, and units. Exploit-resistance takes the first fenced block ahead of grading, and schema-mutation's tracker records a grader that rejected equivalent answers and common wire formats.

\item \textbf{Hidden splits that were not hidden.} Every one of the first \reviewWaveOne{} packages changed its hidden-split handling at 0.2.0. Two failure shapes recur in the changelogs and pull-request threads: a split that reproduced public items (ranking-stability's ordering family regenerated the same prompts; honesty had public-answer overlaps) and a split that could ship inside the npm tarball (sycophancy's publishing leak, recorded in pull request 20; the moved output paths recorded by pelican and payment-delegation; schema-mutation's move into \texttt{.hidden/}, which sits under Unreleased so the measured 0.1.0 lacks it; and silent-constraints' tarball exclusion paired with an \texttt{-{}-out} filename guard). At least \noteHiddenSeedPublished{} packages had also published a way to regenerate the hidden split: hundred-step named the seed in its provenance, ranking-stability served it in task metadata (the later issue 15), sycophancy committed its default hidden seed and generator to the public repository (the council flagged the seed on pull request 20 as an open Major, and the builder removed it before that request merged), and \noteHiddenSeedReadmes{} more READMEs print a concrete seed in the \texttt{-{}-split hidden} example (accessibility-fix, apology-pizza, checkout-consent, cost-per-task, exploit-resistance, mcp-safety, pelican, schema-mutation, skateboard, and test-weakening). Those are examples in current documentation; nothing shows each seed was a real held-out one.

\item \textbf{The SDK task-list cache.} At least \defectTaskListCache{} packages record the same trap: a benchmark object cached its task list, so pointing the SDK at a held-out file silently re-scored the public split. Mcp-safety removed \texttt{setTasksPath} for exactly this reason, skateboard now builds a fresh benchmark per call, and payment-delegation's changelog (under Unreleased) records a twin case, a task file rewritten at the same path being re-read on the next parse.

\item \textbf{Breakdowns the engine dropped.} At least \defectDroppedBreakdowns{} packages record per-row grader details that did not survive the shared surfaces, so each package that promises a breakdown recomputes it in-package. Pelican's \texttt{mcp} command ran the engine's bare server, so \texttt{run\_benchmark} returned no \texttt{checkSummary} until the route was pointed at the package's own server; tool-errors records the identical fix.

\item \textbf{Forged report rows accepted.} Apology-pizza's \texttt{/v1/score-report} trusted the scores it was given, so a forged report returned a mean of \noteApologyForgedMean{}. Its grading notes now state the rule plainly: submitted scores, reasons, means, and intervals are ignored, and every row is re-graded from its tool log. The shared engine already works that way: each package's \texttt{score} command re-grades the submitted rows from their stored submissions, and several packages document the rule on their own surfaces, for example silent-constraints' \texttt{score} and exploit-resistance's \texttt{/v1/report}.

\item \textbf{An evaluator a crafted answer could escape.} Test-weakening 0.1.0 evaluated model-written JavaScript in the benchmark's own process through \texttt{Function(...)} behind a syntax allow-list, and a member name computed at run time could reach \texttt{constructor}. Version 0.2.0 replaces it with a parser and a tree-walking interpreter for a closed grammar inside child processes that can be killed (the pool size is \texttt{EVALUATOR\_POOL\_SIZE = \noteTestWeakeningPoolSize{}} in \texttt{src/sandbox.ts} line \noteTestWeakeningPoolLine{} of the package), and 0.1.0 is deprecated on npm with a security note.

\item \textbf{Documentation ahead of the code.} At least \defectDocsAheadOfCode{} packages published grading notes or README claims for checks that did not exist or numbers nobody had measured. Sycophancy's notes claimed a courtesy check for slurs the pattern did not contain; pelican printed prompt-only solvability numbers that a probing policy then measured lower; hundred-step's README said dependency tokens could not be guessed while its own error messages returned them.

\item \textbf{Generator bugs.} At least \defectGeneratorBugs{} packages shipped generators that broke their own task sets. Accessibility-fix wrote \texttt{href="undefined"} into \noteAccessUndefinedPrompts{} hard prompts, and a stray background draw could make a reference page fail its own grader. Ranking-stability's ordering family never called its own random source, so every ordering answer was the first name in the prompt.

\item \textbf{Lexical detectors that do not generalise.} At least \defectLexicalDetectorMiss{} packages score language with anchored rules that miss unseen wording. Crm-truthfulness scores forbidden-phrase traps by anchored rules. A probing review wrote \noteCrmTrapLines{} unseen trap lines, half obeyed and half honest, and ran each on all \noteCrmTrapTasks{} trap tasks. It missed \noteCrmObeyedMissed{} obeyed lines, and \noteCrmHonestCapped{} honest refusals landed at the \noteCrmTrapCap{} cap, below the vague-email score. The package ships as alpha documenting a different measure of the same weakness: \noteCrmDocHonestPct{} percent of honest refusals (\noteCrmDocHonestRate{}) were scored as honest in its own check, and the rest were missed. Honesty's claim detectors made the same class of error on the prose around a JSON answer and were removed; the graded field is now only the answer.

\item \textbf{Prompts looser than the grader.} At least \defectPromptLooserThanGrader{} packages stated a bound the grader measured more strictly. Pelican's documented limits record a beak ``at least a third'' of the body against a check that needed \notePelicanBeakMin{}, so the package tells the reader to draw with a margin. Honesty scored a confidence field its prompt never defined.
\end{itemize}
