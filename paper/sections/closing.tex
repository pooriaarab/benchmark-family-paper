\subsection{Limits of the evidence}
Everything this paper says comes from \suitePackages{} packages in one family: one shared engine, one pipeline, one maintainer. There is no human-built control, so we cannot separate ``agents build defective benchmarks'' from ``this pipeline builds defective benchmarks''. The reviewers were agents too: sessions the author configured and handed a protocol, run separately from the builders, and their offline model choice is not recorded. The comparison the data supports is between two depths of review: the builders' own gates and the council's diff-reading approvals on one side, probing sessions that run attack policies on the other. The record contains no case of an agent reviewing its own work and no human reviewer, so it says nothing about either.

\paragraph{Error analysis.}
The trivial-policy null has a shape worth naming. The defects it caught, checkout-consent's never-pay credit and tool-errors' do-nothing trace that still collected the safety term, are the ones a package grader paid to a generic output shape. The ones it missed needed the attack to know the task: pelican's memorised SVG scores only when it is the drawing the task asks for, honesty's abstain value is a constant specific to that package's contract, mcp-safety's headline is the product of a safety term and a usefulness term, and sycophancy's is a band match, so one fixed answer stays low in both. A generic policy also cannot exercise the episode surfaces where several of these packages live, because the fake server answers one request at a time. The defect classes the council and the probing sessions logged are task-shaped, and the policies that expose them have to be task-shaped too.

No real model was run for this paper. Every measured number is a property of a grader and a script, not of a language model. The mock separation shows that a grader is not a constant function on its tasks. It does not show that a careful model cannot find a hole the scripted bad policy missed, and it says nothing about whether the suite discriminates between real systems.

Deterministic graders limit what they measure. A grader that checks structure, as pelican does, accepts some drawings a person would reject and rejects some a person would accept. Test-weakening's evaluator accepts a small expression language, so ordinary JavaScript it cannot parse fails even when the tests would pass. Crm-truthfulness ships with a documented lexical miss rate. A score on these packages reports how a replayed trace was graded; it does not measure what an agent intended.

Contamination and saturation are unstudied. Public tasks can be memorized, and each package's contamination note says to generate a hidden split and keep it out of the package; we have not run that protocol against a model, so we do not know how much of any public split is already in a training set. The saturation field in every index entry is \texttt{\suiteSaturation{}} on purpose. Ranking statistics need several model reports; we have the command and not the reports. And \texttt{cost-per-task} depends on a price snapshot a provider can change, so a rerun months later can disagree about dollars even when the tool trace is identical.

\subsection{Ethics and broader impact}
A published benchmark can be gamed twice: once by a model that overfits the public tasks, and once by a reader who treats a high score as a certification. Several packages are about refusal, consent, or not leaking a secret; a high score is not a purchasing decision and not evidence that a deployment is safe. Checkout-consent uses a fake shop and a test payment and must not be pointed at a real card. Mcp-safety uses a canary string and must not be pointed at a production tool server holding real credentials. Silent-constraints and exploit-resistance measure behaviours that matter exactly where the stakes are real; a passing score there deserves the most scepticism.

Test-weakening evaluates model-written expressions in child processes behind a closed grammar. That is still not a security boundary. Run it in a disposable environment, with no keys in the environment and no network it can use. The mock provider only replays committed fixtures, which is the path this paper measured.

The tasks are synthetic or written by the maintainer, except the pelican-on-a-bicycle prompt popularised by Simon Willison and the OpenStax formula citation in skateboard. The pelican package declares CC0 for the canonical prompt and MIT for the seeded grid it generates; we did not verify the prompt's licence ourselves. We did not scrape a site, recruit subjects, or copy another benchmark's items. Sycophancy labels are a judgement about harm made by one maintainer; a second reader can disagree, and the repository says how that disagreement should be handled. The benchmark should not be used to punish a model for a contextual judgement the label got wrong.

Licences are per source, not per package. Table~\ref{tab:suite} lists them: code is MIT, the seeded grids and catalogs are MIT or CC0, the skateboard glossary cites CC-BY material, and the OpenRouter price feed behind \texttt{cost-per-task} carries \texttt{NOASSERTION} because the endpoint states no SPDX licence. The paper text is CC BY 4.0.

\subsection{Reproducibility and availability}
To regenerate the tables, install Node 20 or newer and run \texttt{node scripts/collect.mjs} from a checkout of this repository. The script's only network use is \texttt{npx} resolving the packages named in \texttt{paper/data/suite.txt}. To rebuild the PDF, install Tectonic 0.17.0 and run \texttt{make pdf}; \texttt{make arxiv} builds the submission packet and recompiles it flat. The bootstrap seed and the resample count are the engine defaults unless a caller overrides them. Public task generators use seed \suitePublicSeed{} where the provenance command prints \texttt{-{}-seed}. The defect counts in Section~\ref{sec:review} regenerate from \texttt{paper/data/defects.csv}, the builder and reviewer counts from \texttt{paper/data/builders.csv} and \texttt{paper/data/reviewers.csv} (rebuilt by \texttt{scripts/builders.mjs}), the council counts from \texttt{paper/data/council.csv} (rebuilt by \texttt{scripts/council.mjs}), the fix-round counts from \texttt{paper/data/review-rounds.csv}, and the preregistered trivial-policy scores from \texttt{paper/data/trivial.csv}; their derivations are in \texttt{paper/data/README.md}.

The review log behind Figure~\ref{fig:rounds} is published as release \texttt{review-log-v1} of this repository: \texttt{review-log.tar.gz} (checksum in \texttt{review-log.sha256}) holds the \reviewRoundsTotal{} fix briefs, the re-review protocol that Appendix~\ref{app:protocol} condenses, and the same rounds table, so the fix-round counts repeat from a public artifact~\cite{benchmarkfamily2026reviewlog}. The protocol the first-round defect-finding sessions followed is not part of that release.
