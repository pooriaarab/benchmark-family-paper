\subsection{Limits of the evidence}
Everything this paper says comes from \suitePackages{} packages in one family: one shared engine, one pipeline, one maintainer. There is no human-built control, so the data cannot separate ``agents build defective benchmarks'' from ``this pipeline builds defective benchmarks''. The comparison the record supports is between the builders' own gates and LLM diff review on one side and the probing sessions that ran attack policies on the other. Those reviewers were agent sessions the author configured and handed a protocol; the record does not name the model behind them, and it holds no case of an agent reviewing its own work and no human reviewer, so it says nothing about either.

A selection caveat sits over the defect counts: Table~\ref{tab:defects} is built from the probing record, so ``probing found them'' is partly true by construction. The parts that do not rest on that record are the re-measurements: the exploit clause verdicts in Section~\ref{sec:review}, the trivial battery in Section~\ref{sec:prereg}, and the contract probes in Section~\ref{sec:soundness}. Every wave-2 number is exploratory, because those packages have a single release and some already carry review fixes, so nothing here compares a before and an after for them. The registered real-model arm is unmeasured: the free-model run was not completed, no cells are vendored in this repository, and this paper reports no model numbers.

\paragraph{What the measured numbers still do not show.}
No real model was run for this paper. Every measured number is a property of a grader and a script. The mock separation shows that a grader is not a constant function on its tasks; it does not show that a careful model cannot find a hole the scripted bad policy missed, and it says nothing about whether the suite discriminates between real systems. Deterministic graders also limit what they measure: pelican's structural check accepts some drawings a person would reject, test-weakening's evaluator accepts only a small expression language, and crm-truthfulness ships as alpha with a documented lexical miss rate, so a score on these packages reports how a replayed trace was graded rather than what an agent intended.

Contamination and saturation are unstudied. Public tasks can be memorized, and each package's contamination note says to generate a hidden split and keep it out of the package; we have not run that protocol against a model, so we do not know how much of any public split is already in a training set. The saturation field in every index entry is \texttt{\suiteSaturation{}} on purpose, ranking statistics need several model reports that do not exist, and \texttt{cost-per-task} depends on a price snapshot a provider can change, so a rerun months later can disagree about dollars even when the tool trace is identical.

\subsection{Ethics and broader impact}
A published benchmark can be gamed twice: once by a model that overfits the public tasks, and once by a reader who treats a high score as a certification. Several packages are about refusal, consent, or not leaking a secret, and a high score says nothing about what to buy or whether a deployment is safe; checkout-consent must not be pointed at a real card, mcp-safety not at a tool server holding real credentials, and test-weakening's expression evaluator is not a security boundary. The tasks are synthetic or written by the maintainer, licences are per source (Appendix~\ref{app:reproducibility}), and sycophancy labels are a single maintainer's judgement, so the benchmark should not be used to punish a model for a contextual judgement the label got wrong. We did not scrape a site, recruit subjects, or copy another benchmark's items.
