\subsection{Limits of the evidence}
Everything this paper says comes from \suitePackages{} packages in one family: one shared engine, one pipeline, one maintainer. There is no human-built control, so the data cannot separate ``agents build defective benchmarks'' from ``this pipeline builds defective benchmarks''. The comparison the record supports is between two depths of review: the builders' own gates and the council's diff-reading approvals on one side, and the probing sessions that ran attack policies on the other. Those reviewers were agent sessions the author configured and handed a protocol; the record does not name the model behind them, and it holds no case of an agent reviewing its own work and no human reviewer, so it says nothing about either.

A selection caveat sits over the defect counts: Table~\ref{tab:defects} is built from the probing record, so ``probing found them'' is partly true by construction. The parts that do not rest on that record are the re-measurements: the exploit clause verdicts in Section~\ref{sec:review}, the trivial battery in Section~\ref{sec:prereg}, and the contract probes in Section~\ref{sec:soundness}. Every wave-2 number is exploratory, because those packages have a single release and some already carry review fixes, so nothing here compares a before and an after for them.

\paragraph{What the measured numbers still do not show.}
No real model was run for this paper. Every measured number is a property of a grader and a script. The mock separation shows that a grader is not a constant function on its tasks; it does not show that a careful model cannot find a hole the scripted bad policy missed, and it says nothing about whether the suite discriminates between real systems. Deterministic graders also limit what they measure: pelican's structural check accepts some drawings a person would reject, test-weakening's evaluator accepts only a small expression language, and crm-truthfulness ships as alpha with a documented lexical miss rate, so a score on these packages reports how a replayed trace was graded rather than what an agent intended.

Contamination and saturation are unstudied. Public tasks can be memorized, and each package's contamination note says to generate a hidden split and keep it out of the package; we have not run that protocol against a model, so we do not know how much of any public split is already in a training set. The saturation field in every index entry is \texttt{\suiteSaturation{}} on purpose, ranking statistics need several model reports that do not exist, and \texttt{cost-per-task} depends on a price snapshot a provider can change, so a rerun months later can disagree about dollars even when the tool trace is identical.

\subsection{Ethics and broader impact}
A published benchmark can be gamed twice: once by a model that overfits the public tasks, and once by a reader who treats a high score as a certification. Several packages are about refusal, consent, or not leaking a secret; a high score says nothing about what to buy or whether a deployment is safe. Checkout-consent uses a fake shop and a test payment and must not be pointed at a real card. Mcp-safety uses a canary string and must not be pointed at a production tool server holding real credentials. Silent-constraints and exploit-resistance measure behaviours that matter exactly where the stakes are real; a passing score there deserves the most scepticism. Test-weakening evaluates model-written expressions in child processes behind a closed grammar; that is still not a security boundary, and the package tells operators to run it in a disposable environment with no keys and no network it can use.

The tasks are synthetic or written by the maintainer, except the pelican-on-a-bicycle prompt popularised by Simon Willison and the OpenStax formula citation in skateboard; the pelican package declares CC0 for the canonical prompt and MIT for the seeded grid it generates, and we did not verify the prompt's licence ourselves. We did not scrape a site, recruit subjects, or copy another benchmark's items. Sycophancy labels are a judgement about harm made by one maintainer, and the repository says how a second labeller's disagreement should be handled, so the benchmark should not be used to punish a model for a contextual judgement the label got wrong. Licences are per source: Table~\ref{tab:suite} lists them, with code under MIT, the seeded grids and catalogs under MIT or CC0, the skateboard glossary citing CC-BY material, and the OpenRouter price feed behind \texttt{cost-per-task} carrying \texttt{NOASSERTION} because the endpoint states no SPDX licence. The paper text is CC BY 4.0.
