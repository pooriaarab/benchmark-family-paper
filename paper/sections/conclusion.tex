The finding of this paper is about the depth of review. \suitePackages{} benchmarks built by coding agents passed the shared test job on the last commit of every merged feature pull request, and the LLM council approved \councilMergedApproved{} of the \councilMergedFeature{} merged feature pull requests, and adversarial probing still found defects in every package. The council's approvals were earned by reading the diff, and they were not empty: \councilSeverityApprovedPrs{} of the \councilMergedApproved{} approved merged feature pull requests carry a review that raises an open Critical or Major item, and of the \councilSeverityReviews{} flagged reviews, \councilSeverityFeatureReviews{} sit on merged feature pull requests (\councilSeverityFeaturePrs{} requests) and \councilSeverityChoreReviews{} on chore pull requests. Of the \councilMergedApproved{} approvals, the record documents \approvalDefectCases{} standing behind defects a later review found: pelican's pull request 4, where issue 8 records a memorised SVG scoring 1.0 on every task, and sycophancy's pull request 20, approved while a publishing leak and a grading-note claim the code did not back were still in the tree. Within Table~\ref{tab:defects} the council itself flagged one of the cited defects, the published hidden seed on sycophancy's pull request 20; the publishing leak in the same hidden-split cell and the courtesy claim in the docs-ahead-of-code cell came from the probing review.

The defect classes compress into five checks we now require before any benchmark in this family ships, and we offer them to anyone publishing an agent-built benchmark:

\begin{enumerate}
\item \textbf{Solvable from the model's view.} A policy that reads only what a real model sees must pass every task kind. Unsolvable tasks and prompts looser than their grader fail this check.
\item \textbf{Blind policies lose.} Constant, empty, always-yes, always-refuse, repeated-call, and task-ignoring strategies must score near the floor. Blind-strategy credit was the most common defect in this suite. The preregistered check suggests generic policies alone do not cover it: the package still needs attack policies written against its own task shape (Section~\ref{sec:prereg}).
\item \textbf{Honest answers win.} A correct answer that is differently worded, fenced, or prose-wrapped must score high. Formatting traps and lexical detectors that miss paraphrase fail this check.
\item \textbf{Held out means held out.} A hidden split must differ from the public split in prompts and answers, keep its own ids, stay out of the published package, and never leak the seed that regenerates it.
\item \textbf{Nothing is taken on trust.} Submitted scores, states, and tool results are re-derived by the grader, documentation claims only checks that exist in code, and model-written text never executes in the grader's own process.
\end{enumerate}

These checks are cheap and already scripted into the family's re-review protocol. On this suite a probing pass found defects that green checks and approvals had left in the shipped packages; that is evidence about what each kind of review catches, and it does not show that no defect remains. Results on real models are future work; the engine, the packages, the protocol, and the defect data are public for anyone who wants to run one.
