The defect counts in Section~\ref{sec:review} rest on review records written after the defects were found. To test one claim before seeing outcomes, we registered a small study on Zenodo on 2026-10-16, before the first run cell. The record lives under concept DOI \texttt{10.5281/zenodo.23424272}: version 1.0 is the plan alone (\texttt{10.5281/zenodo.23424273}), version 1.1 added the deviation log (\texttt{10.5281/zenodo.23424493}), and the current version 1.2 is \texttt{10.5281/zenodo.23424604}.

\paragraph{Design.}
\trivialPolicies{} trivial policies (\texttt{trivial-empty}, \texttt{trivial-yes}, \texttt{trivial-ok}, \texttt{trivial-refuse}, \texttt{trivial-echo}, \texttt{trivial-firsttool}, \texttt{trivial-random}, \texttt{trivial-nulljson}) run on a local fake model server (\texttt{trivial-policy-server}) that answers through each package's own \texttt{openai} provider, the same path a real model uses. Each policy ran the \trivialPackages{} first-wave packages at 0.1.0 and 0.2.0: \trivialCells{} cells, \trivialFailures{} failures. The score is the package's own \texttt{mean} from \texttt{run -{}-json}. The grid runner and the analysis are \texttt{eval-matrix} and \texttt{eval-analyze} in \texttt{pooriaarab/scripts} (commits \texttt{13dc1d6} and \texttt{3381492}).

\paragraph{H1 is not supported.}
The registered primary hypothesis says the best trivial-policy score $T(p,v)$ is higher at 0.1.0 than at 0.2.0 in most packages. Table~\ref{tab:trivial} shows what happened. $T$ was higher at 0.1.0 in \trivialHigherOld{} packages (checkout-consent fell from 0.250 to 0.000; tool-errors from 0.212 to 0.000), higher at 0.2.0 in \trivialHigherNew{} (ranking-stability rose from 0.003 to 0.033), and tied in \trivialTied{}. A one-sided exact sign test gives $p = \trivialSignP{}$ on $n = \trivialSignN{}$ packages. The registered smallest effect of interest is a difference in $T$ of 0.10 or more in at least half of the packages; only checkout-consent and tool-errors reach it, so it is not met. The result is a null: \trivialPolicies{} generic policies caught the logged defects in only \trivialHigherOld{} of \trivialPackages{} packages.

\paragraph{What the null means.}
The blind-strategy holes the probing reviewers logged in pelican, honesty, mcp-safety, and sycophancy needed task-aware attacks: a memorised SVG earns credit only when it is drawn for the task being graded, and honesty's abstention value is a constant only a reader of the package would know to send. A generic policy never plays either. Of the \trivialHigherOld{} packages where the best trivial score fell, tool-errors sits in the blind-strategy row of Table~\ref{tab:defects}, and checkout-consent's 0.250 is credit a generic policy earned without completing a purchase, the same class of hole. So the recommendation this paper makes, to run constant or empty policies against a benchmark, does not by itself catch this defect class; the policies that caught it were written per package, against running code.

\paragraph{Still running.}
H2 and H3 concern real models: the per-model mean score difference between 0.1.0 and 0.2.0 with a bootstrap interval over packages, and the Kendall tau between model orderings per package. The deviation log records every change made before any real-model cell finished: one paid run was started and stopped within about two minutes, no cell finished, and the shared key's usage counter rose by at most 0.275 USD (D2); the roster moved from six paid models to five free ones (D3); the models run through a local proxy that refuses any model id not ending in \texttt{:free} (D4); the spending cap is moot at zero planned spend (D5); and one output cap and reasoning effort was set for every real-model request (D6). The runner also takes \texttt{-{}-concurrency}, \texttt{-{}-timeout}, and \texttt{-{}-retries} flags, which change timing and leave the tasks untouched, so they count as operational settings. Both hypotheses are still running at the time of writing, and this paper reports no model numbers.
