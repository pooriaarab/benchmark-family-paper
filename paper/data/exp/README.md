# Experiment data

Generated by the scripts in `scripts/exp/`; each section names its
script and its failure-modes note. Everything here is offline, free,
and reproducible from the pinned tarballs in `scripts/exp/versions.json`.

## E5 hidden-split hygiene audit

Generated by `scripts/exp/tarball-audit.mjs` and
`scripts/exp/hidden-overlap.mjs`; read
`scripts/exp/hidden-audit.failure-modes.md` first.

```bash
node scripts/exp/install.mjs              # populate .exp-cache (once)
node scripts/exp/tarball-audit.mjs        # writes the two CSVs below
node scripts/exp/hidden-overlap.mjs       # about a minute, writes the third
bash scripts/exp/hidden-audit.test.sh     # four-artifact end-to-end check
```

- `tarball-audit.csv` - one row per pinned artifact (34): file count,
  whether `data/tasks.jsonl` ships and how many public tasks it holds,
  files whose paths name a hidden or held-out split, non-public files
  carrying answer-shaped content (with the detector that fired: `name`,
  `keys` or `content`), and the concrete seed values printed near the
  word "seed" in shipped docs, split into plain mentions
  (`doc_seeds`) and lines that also speak of a hidden or held-out
  split (`doc_hidden_seed_examples`). The answer-bearing column lists
  fixtures and generators too; it is a list to read, not a verdict.
- `hidden-census.csv` - the frozen census, one row per artifact: the
  generator script if one parses `--split` itself, which flags it
  takes, its default hidden output path, whether the hidden split
  refuses to run without an explicit seed, whether the shipped CLI
  accepts `--tasks` (needed to grade a generated split), and
  `qualifies`: the artifact can regenerate a hidden split. Four
  artifacts qualify: pelican 0.1.0 and 0.2.0, cost-per-task 0.2.0,
  accessibility-fix 0.1.0.
- `hidden-overlap.csv` - one row per qualifying artifact per frozen
  seed in `scripts/exp/hidden-seeds.json` (five seeds, never the
  public seed 20261015): hidden and public task counts, exact and
  normalised-hash overlap on prompts and on expected answers
  (normalisation is trim, lowercase, whitespace collapse;
  denominators `prompt_pairs`/`expected_pairs` cover only tasks that
  carry the field), and id overlap both exact and after stripping a
  leading `h-`/`h_` prefix (`id_suffix_overlap` catches hidden ids
  derived from public ones).

What this can and cannot support. The audit inspects the shipped
artifacts only: whether held-out data leaked into the tarball, whether
docs print concrete seeds, and whether a regenerated hidden split
duplicates the public one. It says nothing about training-data
contamination - a public-split task can sit in a model's training data
regardless of what the tarball contains. Two findings a reader should
not over-read: pelican 0.1.0 and accessibility-fix 0.1.0 accept a
hidden run without an explicit seed (their generator falls back to the
public seed, which the frozen run never exercises because the seeds are
always passed), and accessibility-fix is a wave-2 package, so its
numbers are exploratory rather than before/after.

## E1 trivial battery

Generated by `scripts/exp/trivial-battery.mjs`; read
`scripts/exp/trivial-battery.failure-modes.md` first.

## How to regenerate

```bash
node scripts/exp/install.mjs              # populate .exp-cache (once)
node scripts/exp/trivial-battery.mjs      # about 5 minutes, writes this dir
bash scripts/exp/trivial-battery.test.sh  # three-package end-to-end check
```

The run shares one `trivial-policy-server.py` process across all cells and
visits them in the registered `eval-matrix` order. The 24 wave-1 artifacts
go first under all eight policies in order (`trivial-empty`,
`trivial-yes`, `trivial-ok`, `trivial-refuse`, `trivial-echo`,
`trivial-firsttool`, `trivial-random`, `trivial-nulljson`), then the 10
wave-2 artifacts run the same eight blocks. `trivial-random` is seeded by
the server's request count, so the run is sequential at `--concurrency 1`
and must stay that way; splitting or reordering cells changes that
policy's draws and can break the replication check. Keeping wave-2 after
the wave-1 blocks is what lets the 192 registered cells reproduce; the
wave-2 arm sits outside the registration and is labelled exploratory.

## Files

- `trivial-battery.csv` - every row of every cell: `package`, `version`,
  `policy`, `task`, `score`, `reason`. Nothing is dropped; failed cells
  that still produced a report keep their rows. Reasons that contain
  commas or quotes are RFC-4180 quoted, so use a real CSV parser, not a
  plain split. Newlines inside reasons are flattened to spaces. The file
  is about 2 MB and is not committed; `node
  scripts/exp/trivial-battery.mjs` regenerates it with the cell table
  below.
- `trivial-battery-cells.csv` - one row per cell: `package`, `version`,
  `policy`, `mean`, `rows`, `tasks`. A cell whose run failed after one
  retry has an empty `mean` and zero `rows`/`tasks`.
- `trivial-reasons.csv` - `package`, `version`, `class`, `count`: how the
  zero-score rows die, using the frozen classes in
  `scripts/exp/reason-classes.json` (`format-gate`, `contract-violation`,
  `wrong-answer`, `abort`). Rows matching no class count as
  `unclassified` and are reported, never dropped; the script warns when
  `unclassified` tops 10 percent of zero rows.
- `trivial-headroom.csv` - `package`, `version`, `oracle`, `best_policy`,
  `best_trivial`, `headroom`. `oracle` is the package's mock `good` mean:
  the mock runs at seeds 1 and 2 are paired so every task contributes its
  good-policy row, the same definition `scripts/collect.mjs` uses for
  `goodMean` in `suite.json`. `headroom = oracle - best_trivial`.
  `best_policy` is the unique argmax policy name, or `tie` when several
  policies reach the best mean. The `tie` label fixes the labelling bug
  where `paper/data/trivial.csv` names `trivial-echo` on all-zero ties;
  `trivial.csv` itself is unchanged here.

## Replication check

On a full run the script compares each wave-1 package's best trivial mean
against `paper/data/trivial.csv` (`old` at 0.1.0, `new` at 0.2.0) within
0.001 - the 192 registered cells. Every mismatch prints and the script
exits nonzero.

## E4 contract probes

Generated by `scripts/exp/contract-probes.mjs`; read
`scripts/exp/contract-probes.failure-modes.md` first.

`contract-probes.csv` is the output of `scripts/exp/contract-probes.mjs`,
which runs the frozen probe list (`scripts/exp/probes.json`, frozen in
PR #87) against all 34 pinned artifacts in about 15 seconds. One row per
artifact x probe cell (578 rows): `package`, `version`, `probe`, `class`
(the probe kind), `result`, `score` (mean probe score over in-scope
tasks), `reason`, `outside_contract`.

`result` is `pass` or `fail` on `yes` cells, `exploratory` on
`exploratory` cells (run and reported, never a defect), `not-runnable`
where a probe could not run as written, and `outside-contract` on `no`
cells (never run; the flag column is `yes` exactly on these). The frozen
scoring rules are stated in `probes.json` and
`contract-probes.failure-modes.md`; the oracle definition is in
`oracle-definition.csv`.

Regenerate with `node scripts/exp/install.mjs` once, then
`node scripts/exp/contract-probes.mjs`;
`bash scripts/exp/contract-probes.test.sh` runs a three-artifact check
twice and diffs the sha256 of the CSV.

Headline of the first run (pinned versions, measured): all 31 promised
honest-variant cells held; 33 `yes` cells failed. Most fails are TYPE B
rules where the frozen list expects an unchanged score (duplicated tool
calls, prompt echo, and score-injection suffixes move several strict
graders off the oracle score); the rest earned credit on blind or
forged content, for example a two-candidate answer scoring on
schema-mutation, fabricated tool results earning retry credit on
tool-errors, and any non-empty answer counting as a communicated
refusal on payment-delegation decline tasks. Exploratory cells are
reported and never counted as defects.

## E6 determinism

Generated by `scripts/exp/determinism.mjs`; read
`scripts/exp/determinism.failure-modes.md` first.

```bash
node scripts/exp/install.mjs              # populate .exp-cache (once)
node scripts/exp/determinism.mjs          # about 5 minutes, writes determinism.csv
bash scripts/exp/determinism.test.sh      # three-package check, runs the matrix twice
```

The matrix is frozen in `scripts/exp/determinism.json`: the released
version of each of the 22 packages (0.2.0 for wave 1, 0.1.0 for wave 2)
under the mock provider at seeds 1 and 2, concurrency 1, 4 and 16, three
repeats each, plus three repeats of the trivial-server path with the
stateless `trivial-echo` policy at seed 1, concurrency 1.

- `determinism.csv` - one row per run: `package`, `version`, `path`
  (`mock` or `trivial-server`), `seed`, `concurrency`, `repeat`, `rows`,
  `mean`, `sha256`, `status`, `uniform`, `node_version`. `sha256` hashes
  the run's canonical row form (one `JSON.stringify([taskId, score,
  reason])` line per task, sorted) so row order under concurrency cannot
  masquerade as drift. `uniform` is `yes` when every run in the row's
  (package, path, seed) group completed and produced the same hash. A
  package counts as byte-identical when all of its mock rows say `yes`;
  the script prints that count as `N/22` together with the names of any
  packages that drifted. `status` is `ok`, `ok-after-retry`, `timeout`
  or `failed`; runs that did not complete carry an empty `sha256` and
  are reported, never dropped.

Different seeds legitimately hash differently: the mock provider picks
its scripted good answer per (taskId, seed), so the comparison is inside
each (package, seed) group, not across seeds. A package whose grader
reads the wall clock (for example `benchmark-latency-budget`, which
bills measured turn time) can drift inside a group; the CSV records the
drift and the run log names the package with the cause read from its
source, instead of smoothing it over.

What this file cannot support: any claim about real-model run variance.
Every run here goes through the deterministic mock adapter or the
vendored trivial server; nothing calls a real model.
